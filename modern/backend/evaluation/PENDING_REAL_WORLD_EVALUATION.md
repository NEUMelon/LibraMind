# 不能用自动化结果替代的评估

后端已提供采集和评估所需的识别日志、候选确认、知识引用及固定检索接口。当前能复核的是接口/事务测试、20条固定查询和20张已有封面缓存基线。

v1.2以下评估条件尚未满足，不能在实验报告里写“已完成”或使用未测的准确率：

1. **真实封面集A**：至少20个馆内版本，每个2张独立实拍图；至少10张馆外书或非图书负例；其中5部作品有多个真实版本。
2. **真实版权页集B**：至少20张版权页照片及人工核对的字段真值。目前只有合成排版输入的接口检查，不是实拍质量评估。
3. **独立检索标注**：目前20条查询的单目标标签由开发助手根据书名整理，尚未经过独立人工评审，查询偏容易；不把它说成人工相关性金标准。
4. **可用性研究**：正式Vue前端完成后，再邀请3至5位同学做固定任务。当前原生验证页没有经过这项研究。

建议目录：

```text
evaluation/private-photos/
  covers/<case-id>-1.jpg
  covers/<case-id>-2.jpg
  negatives/<case-id>.jpg
  copyright/<case-id>.jpg
  labels.json
```

labels记录caseId、真实editionId/workId、可见字段、拍摄条件、是否馆外/非图书、人工确认的结果。照片可能包含私人背景信息，应先裁除并核对；私有照片默认不进入发布包。

统计时分开报告作品命中与唯一版本命中；候选集合包含正确版本不等于模型确定了该版本。负例不足时不报拒识质量或错误确认率。遇到字段不可见，真值应标注不可判定，不能要求模型凭记忆补全。

已有报告保留失败、耗时和逐项输出。若后来改检索或提示词，保留旧基线和固定测试集，不挑选更容易的样本来制造提升。
