## 结论先说

- 不依赖模型的功能（登录、会话与 CSRF、四个课程模块的增删改查、借还续借与更正、幂等、导入、条码、标签、知识资料、统计、审计、权限隔离、确认卡的准备 / 取消 / 确认 / 恢复）**全部连真实后端和 MySQL 验证通过**。
- AI 助手的 SSE 链路（流式增量、工具调用记录、确认卡生成与刷新恢复、模型中途失败、主动断开）用**本地模拟模型（Mock）**验证通过。这只能证明前后端协议、状态处理和业务保护是对的，**不能**说明真实模型的回答、工具选择或识图质量。
- 真实 `qwen3.5-flash` 对话、封面识别、版权页编目、语义 / 混合检索的向量部分、单本书问答：**未验证**（网络不允许）。

## 2. AI 对话：本地模拟模型（Mock）

做法见前端 README 的“本地模拟模型”一节，代码在 `e2e/mock-provider/`。后端代码和模型名不变；只在测试期间把 `aihubmix.com` 解析到本机的模拟 HTTPS 服务，后端用占位 Key，真实 Key 不会发出去。截图右上角的红色“Mock 模型 · 非真实 AI”是测试脚本加的标记，产品界面里没有。注意此时后端 `meta.mode` 仍是 `live`，界面也会显示“实时模型”，因为后端并不知道对端是模拟服务。

接口级 `e2e/sse-check.mjs`：16/16 通过。

| 检查 | 观察到的事件 / 结果 |
|---|---|
| 检索问答 | `meta → tool → delta×70 → result → done`，`Content-Type: text/event-stream`；delta 拼接与 `result.content` 完全一致；`editionReferences` 有 5 个版本；消息已保存 |
| 续借 | 工具 `getMyLoans → prepareRenew`，只生成 `RENEW / PENDING` 卡，借阅未变 |
| 确认卡恢复 | `GET /ai/actions?conversationId=` 能取回 PENDING 卡 |
| 取消后再确认 | 取消返回 `CANCELLED`；再点确认仍是 `CANCELLED`，续借次数不变 |
| 模型擅自挑一册借书 | 用户没写登录号，模拟模型自己拼了一个登录号调 `prepareBorrow`：后端返回 `INVALID_ARGUMENT`，没有生成卡 |
| 用户写明登录号借书 | 只生成 `BORROW / PENDING` 卡，副本仍在架 |
| 模型中途断开 | `meta → delta → error(AI_UNAVAILABLE)`；该轮不保存半截回答 |
| 客户端主动断开 | 收到 3 段 delta 后中止；同一会话随后可以继续提问并正常完成 |

浏览器里（`flows.cjs` 的 AI 步骤，截图 22–28）：流式光标 → 渲染 Markdown 和版本卡片；续借卡出现后**刷新页面**，卡片从服务器恢复，点击“确认续借”后应还日从 2026-11-26 变为 2026-12-26；“停止生成”后标明本轮不完整并提供“从服务器恢复”；模型中途失败显示错误码和请求号。

## 3. 后端自带的录制回放（replay）

后端 `data/replays/` 有 2 份 2026-10-27 真实录制的 `qwen3.5-flash` 输出。以 `APP_AI_MODE=replay` 启动后，用 README 给出的精确问题测试：

- 第一轮（调用 `queryLibraryPolicy`）命中录制，工具真实执行；
- 第二轮（根据工具结果作答）返回 `REPLAY_MISS`。按后端说明，这是工具输出或上下文与录制时不同导致的预期保护（本环境的数据是重新导入的），不是前端问题。界面显示“回放模式 · 非实时回答”徽标和 `REPLAY_MISS` 错误（截图 29）。
- 未录制的问题直接 `REPLAY_MISS`。

所以回放也没能给出一次完整的真实模型回答。

## 4. 真实模型（live）

后端以 `live` 运行、Key 来自环境变量时，助手请求得到 `meta → error(AI_UNAVAILABLE)`，界面按“AI 服务当前不可用”处理，普通检索与借还不受影响；“混合检索”退回关键词并显示降级提示。

## 5. 联调中发现并已修复的前端问题

| 问题 | 原因 | 修复 |
|---|---|---|
| 批量导入点“执行导入”无反应 | `Intent` 用 `structuredClone` 固定请求体，Vue 响应式数组会抛 `DataCloneError` | 改为 JSON 深拷贝（请求体本来就是 JSON），并补单元测试 |
| 助手流式接口 500 | 发送了 `Accept: application/json`，后端 SSE 端点 406 后被统一异常处理成 500 | 流式请求改发 `Accept: text/event-stream` |
| 审计详情字段是英文名、时间是 ISO 原文；新增 / 停用只有单侧快照却画成“删除线” | — | 字段中文名、时间本地化；单侧快照按“新建的记录 / 操作前的记录”展示 |
| 知识资料列表只显示 100 条却按全部计数 | 后端 `GET /knowledge` 只返回最近 100 条且不分页 | 页面注明，并增加按版本编号查询（后端已支持 `editionId`） |

## 6. 对后端的观察（未修改）

这些不影响前端完成任务，按“非必要不改后端”的要求只记录：

1. `POST /ai/conversations/{id}/stream` 在 `Accept` 不含 `text/event-stream` 时返回 500，而不是 406。
2. `GET /knowledge` 最多返回最近 100 条，不分页。
3. Mock 测试中，客户端中止 SSE 后，模拟服务在之后约 20 秒内没有看到后端关闭上游连接，说明中止可能没有及时传到模型请求；真实环境下可能多消耗一些 token。需要真实网络再确认。
4. 审计记录只有 `operatorId`，界面只能显示“#1”，没有账号名。
5. 回放录制与数据强绑定，换一套演示数据后第二轮就会 `REPLAY_MISS`。
